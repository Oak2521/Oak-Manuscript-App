# WEBSITE_INTEGRATION — 网站对接与 Provider 接口

> 依据方案 §11.4、§8.3–§8.5、§10。网站用户系统（Supabase + Netlify Functions 路线）已在网站项目分支开发完成但**未合并上线**（核对快照 2026-07-11，详见 `湖岸稿件_网站配套页面现状对照_20260711.md`）。核心功能不依赖网站；一切对接经 Provider 接口，后接不改变本地核心与项目文件格式。

## Provider 一览（第一版全部为本地占位）

| Provider | 第一版行为（占位） | 未来对接目标 |
|---|---|---|
| `AuthProvider` | 返回「即将开放 / 未登录」；不发起任何网络请求 | 网站 Supabase 认证（邮箱 + Google OAuth），PKCE 兼容 |
| `LicenseProvider` | 本地免费模式；永不锁本地文件 | Pro 年费授权与设备管理（≤3 台） |
| `EvaluationProvider` | 仅生成本地脱敏摘要文件；不发送 | 用户确认后提交脱敏摘要（§8.3–§8.4） |
| `SyncProvider` | 仅记录用户同步偏好到本地；不联网 | 分级检查记录同步（§8.5：一级默认 / 二级可选 / 三级每次单独确认） |
| `StandardsProvider` | 读内置规则包 | 签名规则包更新 |
| `UpdateProvider` | 无操作 | 签名应用更新 |
| `FeedbackProvider` | 本地记录不含正文的规则反馈 | 用户主动发送 |

## 占位实现的硬性验收（对应 §20.1 / §21）

- 未登录状态**不触发**任何同步询问与网络调用；
- 占位 Provider 代码路径中不存在任何真实网络请求；
- 同步负载 JSON schema 带版本号，`project.json` 记录同步状态（时间、范围、检查版本），第一版即冻结 schema 以保证后接不改格式。
